# Lumenfold 界面规范

> 适用范围：桌面端（Lumenfold 主应用）。与 `docs/ARCHITECTURE.md`（宿主分层）配套，本文件只管界面。
> 主题令牌由 `@lumenfold/tokens` 提供，插件跟随宿主主题的唯一契约。

---

## 1. 设计取向

Lumenfold 是桌面端照片资产管理器，面向严肃的摄影师与档案管理者。这两个身份决定了界面语言：工具型，密度高，信息优先，操作可预测。不是一个营销页，不是一块仪表盘，也不是一个只有精选照片的看图工具。

三条设计判据：

- **密度**：档案管理者一屏要看进尽可能多的资产，且每张能读出尺寸、评分、标记这些元数据，不是只看见一个色块。
- **工具感**：界面要让用户确信自己在操作一台设备，而不是在浏览一个网站。控件位置固定、状态可见、快捷键一致。
- **克制的表现力**：颜色和动效服务于识别与反馈，不用于装饰。界面永远不与照片本身争夺注意力。

### 设计档位

| 档位 | 取值 | 说明 |
|---|---|---|
| `DESIGN_VARIANCE` | **4** | 中等偏离 |
| `MOTION_INTENSITY` | **3** | 轻量动效 |
| `VISUAL_DENSITY` | **7** | 高密度 |

**为什么 `DESIGN_VARIANCE = 4`。** 营销页的默认值通常在 8 到 10，代价是大圆角、超大标题、留白主导的构图。这套布局要让用户在同一屏内比较三十张缩略图的构图与曝光，任何偏离轴线的装饰都会让并排比较变难。取 4 表示允许分区层级、手风琴折叠、检查器这类有明确语义的形态变化，同时保持栅格对齐、控件形态与间距规则的统一。低于 3 会退化成一张报表，高于 5 会让工具显得松垮。

**为什么 `MOTION_INTENSITY = 3`。** 只用 CSS transition，不引动画库，不做滚动劫持，不做常驻循环动效。理由是主界面是一块 60fps 滚动照片网格，缩略图解码与合成已经占满主线程预算，任何额外的主线程动画工作都会直接体现为掉帧。动效在这里唯一的作用是让状态变化可被感知，而不是展示技巧。低于 3 会显得生硬，高于 4 就会有人开始加动效库，那一步应当重新评估而不是顺手做掉。

**为什么 `VISUAL_DENSITY = 7`。** 摄影师的真实资产库里，筛选与评级的工作量远大于浏览单张。密度 7 意味着行高压缩、间距收紧、次要信息降级为弱对比文本，把纵向空间让给更多行元数据。代价是留给留白的空间很少，界面看上去偏紧，这是有意的取舍：留白对这个用户群是浪费而不是品味。低于 6 会让 1000 格视口只能看到很少的可操作资产。

## 2. 应用外壳布局

外壳用三层 flex 纵向叠放（标题栏 / 中部行 / 状态栏），中部行再横向切成侧边栏、内容区、检查器三列。选 flex 而不是 CSS Grid 的原因很实际：只有内容区的高度需要随窗口伸缩，左右两列是固定宽度或可折叠宽度，用 flex 的 `min-w-0` 就能把横向溢出掐死，不需要额外的 `minmax(0, 1fr)` 声明。

```
外层：flex-col
├─ 标题栏        h-9（36px） 固定
├─ 中部行        flex-1  min-h-0  relative
│  ├─ 侧边栏      216px / 折叠 56px  shrink-0
│  ├─ 内容区      flex-1  min-w-0
│  └─ 检查器      280px  shrink-0（窄窗转绝对定位覆盖层）
└─ 状态栏        h-7（28px） 固定
```

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 标题栏 | 36px | 产品标记、当前图库路径、窗口控件 |
| 侧边栏 | 216px，折叠为 56px | 主导航 |
| 工具栏 | 44px | 排序、密度、选择计数、搜索入口 |
| 内容区 | `flex-1 min-w-0` | 视图容器，**唯一滚动容器** |
| 检查器 | 280px，可折叠 | 预览、元数据、关键词、说明 |
| 状态栏 | 28px | 计数、缓存占用、图库路径、主题切换 |

内容区是整个应用唯一的滚动容器。侧边栏、工具栏、标题栏、状态栏都不滚动。检查器内部可滚动，那属于检查器自身的局部滚动，不改变这条规则。

### 标题栏（36px）

从左到右：产品标记、当前图库路径（过长时省略，`title` 显示完整路径）、资产计数、右侧窗口控件。

窗口控件按平台自绘：

- **Windows / Linux**：最小化 / 最大化 / 关闭，右侧对齐，关闭按钮 hover 转 `danger`。
- **macOS**：左侧预留 **72px** 空位给系统红绿灯，宿主不绘制、不覆盖。

整条标题栏带 `data-tauri-drag-region`，窗口可拖动。控件容器带 `no-drag`，保证点按钮不会变成拖窗口。

### 侧边栏（216px / 56px）

五个入口，顺序固定：

1. 图库
2. 时间线
3. 人物
4. 搜索
5. 设置（固定在底部，与主导航分组）

**地点与相册不放进导航**。它们分别属于 M6 与 M2，入口在功能落地之前不出现。宁可少两个菜单项，也不要放两个点开就告诉用户「还没做」的死入口。

展开态为图标加文字单行；折叠态为 56px 纯图标栏，图标居中，`title` 与 `aria-label` 提供文字标签。底部另有图库概况块（读取方式、网络传输），以及折叠按钮。折叠状态由用户控制。

### 工具栏（44px）

工具栏有**两种互斥状态**，不做同屏共存：

**浏览态**（无选中项）

- 排序：下拉（拍摄时间 新到旧 / 旧到新 / 文件名 / 文件大小 / 评分）。
- 缩略图密度滑块：连续调节目标行高，120px 到 360px，步长 20。
- 右侧：搜索入口、检查器开关。

**选中态**（有选中项）

- 「已选 N 项」计数、取消选择。
- 其余位置留给 M2 的批量动作，此处不做占位按钮，只有一行文字说明这批功能属于哪个里程碑。

视图切换只出现在侧边栏，工具栏不再重复同一组入口。

工具栏在内容区滚动时保持不动。

### 工具栏的适用范围

工具栏只出现在图库与时间线。人物与设置是整页视图，密度滑块和排序在那里没有意义，不出现工具栏。搜索视图顶部换成检索栏（输入框 + 文本/语义分段控件 + 清除）。

### 内容区

图库视图与时间线视图共用这一个容器：

- **图库**：单层 justified 网格，按密度滑块给出的行高切行。
- **时间线**：按月与日分组，分组头也是虚拟列表里的一种「块」，行高固定，因此整条时间线同样是纯算术定位，不需要逐块测量。滚动时顶部吸附当前日期。

**约束**：内容区必须设置 `min-w-0`。flex 子项默认的 `min-width: auto` 会让内容把容器撑开，这是横向溢出的头号来源。

### 检查器（280px，可折叠）

只在图库与时间线出现，显示单选项的：

- **预览**：3:2 缩略图。
- **评分**：0 到 5 星，只读展示。写入属于 M2。
- **文件**：尺寸、像素量、大小、拍摄时间、方向、完整路径。
- **拍摄参数**：机身、镜头、光圈、快门、感光度、焦距、GPS。两列网格，字段名定宽，数值列等宽字体。
- **关键词**：只读标签。增删与写回属于 M2。
- **说明**：照片说明文字，可选中复制。

多选时只显示数量，不猜用户想看谁的照片参数。未选中任何项时显示操作提示。

### 状态栏（28px）

从左到右：演示模式标记（仅浏览器预览时出现）、资产总数、已选数量、缓存占用、图库路径、主题切换按钮。全部数字用等宽数字。

索引任务进度在 M0 的任务队列就位后加入，位置预留在「已选数量」与「缓存占用」之间。

### 响应式断点

| 断点 | 行为 |
|---|---|
| `< 1180px` | 检查器从第三列转为绝对定位覆盖层，内容区宽度不被挤压 |
| `< 1024px` | 侧边栏自动折叠为 56px 图标栏，由 `useMediaQuery` 驱动，不是散落的媒体查询类名 |

**约束**：内容区最小宽度为 `0`。任何断点都不允许出现横向溢出。不设下层断点，不做移动端布局，这是桌面应用。窗口最小尺寸 960×600，由窗口配置保证。

### 为什么是琥珀色

单一强调色取琥珀色，取自暗房安全灯。三条理由：

1. **它读起来是界面，不是照片内容。** 照片的色域极宽，界面强调色若落在红绿蓝的中高饱和区，很容易和用户照片里的同色区域混淆，用户会本能地把它当成图像的一部分。琥珀色落在照片内容分布稀薄的长波区，与摄影内容区分度足够高。
2. **它在两套主题里都成立。** 暗色下用亮琥珀（`#F2A93B`）作为亮部点缀，亮色下用深琥珀（`#9A5B00`）保证文字对比。同一语义在两套主题中保持同一色相，用户不需要重新建立「强调色是什么」的认知。
3. **它不是 AI 紫色。** 紫色渐变是当前 AI 产品的事实默认色。Lumenfold 的差异化在档案能力与本地优先，不在模型，用 AI 紫色会把这个产品误读成一个模型演示。

琥珀色是单色相，不代表只能用琥珀。它是唯一强调色的位置，危险用 `danger`，成功用 `success`，不再引入第四种彩色。

### 对比度实测

以下比值按 WCAG 2.1 相对亮度公式计算，非估算。

**暗色主题**

| 组合 | 比值 | WCAG AA |
|---|---|---|

| `text` on `surface` | 15.30 | 通过 |
| `text-2` on `bg` | 7.51 | 通过 |
| `text-3` on `bg` | 5.11 | 通过 |
| `text-3` on `surface` | 4.78 | 通过 |
| `accent-ink` on `accent` | 9.26 | 通过 |
| `accent` on `bg` | 9.80 | 通过 |
| `danger` on `bg` | 5.00 | 通过 |
| `success` on `bg` | 7.70 | 通过 |

**亮色主题**

| 组合 | 比值 | WCAG AA |
|---|---|---|
| `text` on `bg` | 16.76 | 通过 |
| `text` on `surface` | 17.98 | 通过 |
| `text-2` on `bg` | 5.76 | 通过 |
| `text-3` on `bg` | 4.89 | 通过 |
| `text-3` on `surface` | 5.24 | 通过 |

## 4. 字体

### 字体族

- 拉丁文与数字：**Geist Variable**，数字部分与表格数值另用 **Geist Mono Variable**。
- 通过 `@fontsource-variable` 引入，本地打包，不依赖 CDN。

### CJK 回退链

界面是中文，而 Geist 不含 CJK 字形。缺这一条，中文界面会掉到系统默认字体，中英混排的字重与字宽会明显对不上。

```
font-family: "Geist Variable", "Geist", "PingFang SC", "HarmonyOS Sans SC",
  "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC",
  -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

Geist 只含拉丁字形，中文必然回落到后面的 CJK 字体，所以 CJK 字体必须紧跟在 Geist 之后，不能夹系统西文字体在中间，否则中文会先落到一个没有汉字的西文字体上，再靠它继续回落，多一层不确定性。`PingFang SC` 覆盖 macOS，`HarmonyOS Sans SC` 与 `Microsoft YaHei UI` 覆盖国产与 Windows，`Noto Sans CJK SC` 覆盖 Linux 并作为兜底。数字与代码用 Geist Mono Variable 加 `tabular-nums`。

### 字号阶梯（px）

| 令牌 | 值 | 用途 |
|---|---|---|
| `2xs` | 11 | 角标、状态栏次要项 |
| `xs` | 12 | 元数据表字段名、辅助说明 |
| `sm` | **13** | **基准字号**，正文、按钮、列表项 |
| `md` | 15 | 面板标题 |
| `lg` | 18 | 区块标题 |
| `xl` | 22 | 空状态标题 |
| `2xl` | 28 | 仅用于首启引导等极少场景 |

基准字号 13px 而非 14 或 16，是为了在高密度下容纳更多行，同时保持可读。

### 数字

表格数值列、状态栏计数、文件尺寸、时间戳、坐标一律使用 **Geist Mono**，并开启 `font-variant-numeric: tabular-nums`（等宽数字）。原因是这些数字需要纵向对齐以便快速比较，等宽数字列才不会因位数变化而抖动。

## 5. 圆角

一条规则，三档，不混用：

| 档位 | 值 | 用途 |
|---|---|---|
| 缩略图 | 2px | 缩略图、网格单元、图像容器 |
| 控件与面板 | 6px | 按钮、输入框、下拉、检查器、弹层、卡片 |
| 胶囊与头像 | 999px | 标签 chip、人物头像、状态指示点 |

**不要出现第四种圆角**，也不要让同一个控件在不同状态下改变圆角。2px 刻意保持锐利，缩略图被大圆角切开会让拼贴式比较失真；999px 用于胶囊语义，任何需要判断边界的东西（按钮、面板）都不用它。

## 6. 动效

`MOTION_INTENSITY = 3` 的展开规则：

- 只用 CSS transition。**不引入动画库**。
- 不做滚动劫持，不做视差。
- 不做常驻循环动画（呼吸、脉冲、旋转指示除外，且仅用于确实在进行的任务）。

| 项 | 值 |
|---|---|
| 快速（hover、按下、焦点环） | 110ms |
| 标准（展开、折叠、切换、面板进出） | 160ms |
| 缓动 | `cubic-bezier(.2,.6,.2,1)` |

只对 `transform` 与 `opacity` 做过渡。改变 `width`、`height`、`top` 会触发布局，在滚动中的网格里必然掉帧；需要尺寸变化时用 `grid-template-rows` 过渡或直接切换。

**应用主界面是 60fps 滚动照片网格，动效在这个界面上的预算上限就是「不掉帧」，不是「好不好看」。**

### 减弱动效

`prefers-reduced-motion: reduce` 下，所有 transition 与 animation 归零，不只是缩短时长。这条规则作用于每一个 transition，没有例外，也不提供局部豁免。

## 7. 可访问性

### 焦点

每一个可交互元素都有可见焦点环。焦点环用 `accent` 绘制，偏移 2px，不依赖 `outline: none` 的默认样式。焦点环在暗色与亮色主题下都必须可见。

不得出现「点击后焦点丢失」：任何关闭弹层、切换视图、增删网格项的操作后，焦点必须落到一个合理位置，通常是原触发元素或网格中的相邻项。

### 网格语义

内容区使用 `role="grid"`：

- 容器 `role="grid"`，行 `role="row"`，单元格 `role="gridcell"`。
- **roving tabindex**：整个网格在 Tab 序列中只占一个停靠点，方向键在网格内部移动活动单元格。这让 Tab 键能跳过成百上千个格子，直接到达检查器。
- 每行需要 `aria-rowindex`，网格需要 `aria-rowcount` / `aria-colcount`，让屏幕阅读器播报「第 3 行第 5 列，共 2000 项」。
- 单元格的可访问名包含文件名与关键元数据，不能只有图像。

### 键盘映射

| 按键 | 行为 |
|---|---|
| 方向键 | 在网格中移动光标。左右走摊平顺序，越过行尾落到下一行开头；上下按当前行列数跨行。没有光标时先落到第一项 |
| `Shift` + 方向键 | 移动光标并连选 |
| `Space` / `Enter` | 切换光标项的选中状态 |
| `Ctrl+A` / `Cmd+A` | 全选 |
| `Home` / `End` | 光标跳到首项 / 末项 |
| `Esc` | 清除选择与光标 |
| `/` | 跳到搜索视图 |

**不做的快捷键**：`1` 到 `5` 的评分快捷键等写入类操作属于 M2，元数据写回没就位之前不做半截实现。`G` / `T` / `P` 之类的单字母跳转也不做，它们没有对应菜单项时只会制造误触。快捷键要么对应一个看得见的入口，要么不做。

### 选中态不得只靠颜色

选中状态**必须由颜色以外的通道同时表达**。至少满足其一，并且始终成立：

- 2px 强调色外描边（与未选中的 1px `border` 同时存在，描边粗细本身也不同）
- 右下角的实心对勾角标
- 工具栏与状态栏的选中计数

原因有两个。色觉障碍用户无法从蓝黄等色相差分辨选中态，这是可访问性底线；另外本应用的默认强调色是琥珀色，与照片内容里常见的暖色区域相邻，仅靠底色变化判断选中是不可靠的。

旗标固定在左上角，评分星只在未选中时出现，两者不共用位置，避免叠在一起互相遮挡。

同理，评分星级同时用填充形状与数量表达，不只靠星星的颜色深浅。

---

### 首屏：还没有打开图库

宿主尚未收到任何目录时，内容区渲染**首屏状态**而不是错误页。一个还没指向任何目录的图库管理器是正常状态，把它画成错误页会让用户以为软件坏了。

- 标题「还没有打开图库」，正文说明只读、不搬动原图、索引留在本机。
- 主操作「选择目录」拉起系统目录选择器（tauri-plugin-dialog）；次操作「重新扫描」对已记录的目录再扫一次。
- 目录选择器只在桌面宿主里存在。浏览器 `pnpm dev` 没有这个能力，此时按钮禁用并说明原因，不给一个点了没反应的控件。

### 扫描进行中

扫描在后台线程进行，宿主以 `scanning: true` 与持续增长的计数报告进度。

- 标题栏显示「扫描中 N 项」，状态栏显示「正在扫描目录」，都是强调色文字，不用彩色圆点。
- 界面每 400ms 轮询一次统计，扫描结束后停止轮询。
- 扫描过程中网格照常渲染已登记的照片，不做全屏遮罩：正在增长的内容本身就是进度。

### 读不出尺寸与无法解码的资产

RAW 与 HEIC 在 libvips 管线就位前没有解码器，宿主会对它们返回 404。网格此时渲染一个写明文件名的占位格，而不是浏览器默认的破图图标；排版用 3:2 中性比例占位，比例只影响格子大小，不冒充真实尺寸。

## 8. 当前实现状态

本节记录 M0 阶段界面的真实边界，避免规范被误读成功能清单。

### 已落地

- 应用外壳的全部六个区域与两处响应式降级。
- 图库视图：justified 虚拟网格、密度滑块、排序、单选/多选/连选、键盘导航、检查器联动。
- 时间线视图：按月日分组、固定高度虚拟列表、吸附日期头。
- 人物视图：聚类卡片 + 识别模型未就绪提示。
- 搜索视图：文本检索（真实查本地字段）；语义检索如实说明「向量索引未就绪」。
- 设置视图：主题切换、模型注册表（非商用标识显式呈现）、存储概况。
- 加载态用按最终形状铺的骨架屏，错误态就地展示宿主返回的原始信息。
- 首屏「还没有打开图库」、扫描进行中的进度、无法解码资产的占位格。

### 尚未落地

- 评分与元数据写入（属 M2）。界面上不放置禁用按钮占位，只写明属于哪个里程碑。
- 索引任务队列与进度（属 M0 后段）。状态栏预留了位置。
- 地图、相册、相似聚类（属 M6）。入口不进导航。
- 模型下载器的续传与 SHA-256 校验（属 M4）。当前点击下载会如实返回宿主的错误，不伪造进度。

### 数据来源

界面只通过 `src/lib/ipc.ts` 的 `bridge` 与宿主通信。Tauri 宿主可用时走命令；宿主不可用时（浏览器里跑 `pnpm dev`）由 `src/lib/fixtures.ts` 的演示图库接管，用于评估布局。

演示模式下状态栏常驻「演示图库」标记，设置页的模型清单会声明体积与校验值均为示例数据。这条标记不能省：让用户把占位图库误认成真实索引结果，比没有预览糟糕得多。

宿主用错误 `kind` 区分状态，界面据此分流，不靠文案匹配：

| `kind` | 界面表现 |
|---|---|
| `no_library` | 渲染首屏状态，提示选择目录 |
| `not_indexed` | 就地错误态，说明依赖的索引或模型尚未就位 |
| `unsupported` | 就地错误态，附宿主给出的原因 |
| `io` | 就地错误态，附原始信息与重试 |

### 缩略图取址

缩略图不走 IPC，网格直接用 `<img src>` 请求自定义协议 `lumen://thumb/<资产 id>?w=<像素宽>`，由浏览器负责缓存、解码与并发调度。宽度被宿主夹在 64 到 1024 之间。

协议取不到图时（未知 id、文件读不了、RAW 与 HEIC 等当前没有解码器的格式）宿主返回 404，界面渲染写明文件名的占位格，不显示浏览器默认的破图。排版用 3:2 中性比例占位，比例只决定格子大小，不冒充真实尺寸。
